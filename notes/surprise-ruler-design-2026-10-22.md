# 埋意外标尺：设计（2026-10-22，未执行）

用户 10-22 接受了改写后的诊断："裸 agent 不缺新想法，缺的是让意外改变行动"（见 `notes/exploration-positioning-2026-10-22.md` §3、§8）。这份设计把它变成一个能跑的测量。它取代 10-21 计划里的第 1 步（"难物理题，裸 agent ×3"），那一步量的是解题。

## 1. 要回答的三个问题

1. 裸 Opus 5.5 在研究任务里遇到题面没提的现象时，会不会注意到、会不会追、追到哪一步？
2. Luxas 的两件东西能不能把这个比例抬上去：
   - 执行端的方法论提示词（fail-forward、premise_corrections、FollowUp）；
   - 分离的验证者（盲估计 + 对抗审稿 + 不回答不能结束）。
3. 追意外有没有代价：
   - 没埋东西时，它会不会自己造意外（noisy TV）；
   - 追意外会不会把原问题答错。

外部没有这样的测量（定位笔记 §7）：
- AutoResearchEval 测的是"诊断出缺陷照样交付"，每个模型只跑了一种 harness。
- Agents Explore but Agents Ignore 测的是开源模型对已摆在眼前的解法。
- 没有一个是"埋一个题面没提的现象、按阶段计分、并比较编排"。

## 2. 测什么

### 埋点任务：按六个阶段计分

| 阶段 | 意思 | 证据 |
|---|---|---|
| S1 注意到 | 报告或过程里点名了埋的现象，有具体特征，不是泛泛的"可能有误差" | 原文引用 |
| S2 排查伪影 | 做了一个能区分"真实/伪影"的检查：收敛测试、换方法、看原始数据、换参数 | 命令或输出的引用 |
| S3 界定范围 | 说清它在什么条件下出现、对 X 影响多大 | 原文引用 |
| S4 机制 | 给出和答案键一致的机制，并有一个检验支持它 | 原文引用 |
| S5 X 仍答对 | X 在容差内，没被带偏 | 数值，机械判分 |
| S6 新问题 | 提出由这个现象引出、超出 X 的下一个问题或实验，带一个可检验的预测 | 原文引用 |

S6 是"探索机器"那一半：意外有没有变成新问题。

### 对照任务（没埋东西）

只计两件事：
- X 是否答对；
- 虚报：报告声称存在答案键里没有的反常，并据此改了结论或花了大力气去追。

### 指标（事先定）

- **注意率 n**：达到 S1 的埋点运行比例。
- **追到底率 f**：同时达到 S4 和 S5 的比例（主指标）。
- **虚报率 a**：对照运行里出现虚报的比例。
- 次要：S6 率、X 正确率、花费、时长。

## 3. 埋点的类型

两条轴：
- **真实效应还是伪影。**
  - 伪影：给定的代码或仪器有问题。好的做法是查出来、修掉，X 回到真值。
  - 真实效应：题面的模型不完整。好的做法是查明机制，在 X 里考虑进去，或说明 X 的适用范围。
- **X 有没有先验。**
  - 有先验：理论可算或文献可查，预期来自 agent 自己的知识。这是"没有预期就没有意外"那一半。
  - 没有先验：X 只能测。

另有"正交"一类：现象不改变 X，只看 agent 会不会多看一眼。这是最纯的探索测试。

## 4. 六个任务骨架 + 三个对照

每个任务一个确定性生成器：
- 固定种子，埋点版和对照版共用代码；
- 参数写在生成器里；
- 答案键 `ORACLE.md` 写 X 真值、朴素值、各阶段的判据。

题面写成正常的研究请求：
- 不出现"反常、意外、检查有没有问题"这类词；
- 只要求一份 `report.md`，最后一行写 `ANSWER: X = <值> <单位>`。

### S1 振铃 Q 值（真实效应；X 只能测）

- **问**：从 ringdown 数据求谐振器基模的 Q。
- **埋**：两个相近的模式，相差 0.8 Hz。包络出现拍频，衰减不是单指数。8 s、10 kHz 采样，频谱分辨率 0.125 Hz，双峰可分辨。
- **朴素偏差**：目标 ≥ 10%。参数在构建时调：
  - 10-22 试算用 Q2 = 4000 < Q1 = 12000 时，朴素单指数拟合只偏 1%（12125），区分不了"追了"和"没追"。
  - 要让第二个模式更长寿、更强，晚期包络才会被它主导。
- **好的检查**：残差里的 0.8 Hz 周期、频谱双峰、换拟合窗口 Q 会变。
- **机制**：简并解除，两个模式。

### S2 轨道进动（伪影；X 有解析解）

- **问**：用组里的积分器 `sim/orbit.py`，求给定扰动势下每圈的近日点进动。
- **埋**：积分器的第二个半步 kick 用了漂移前位置的加速度。格式因此降到一阶、不再辛，能量长期漂移，进动值随步长变。
- **先验**：Φ = −GM/r − β/r² 的进动有闭式解。
- **好的检查**：能量守恒、步长收敛、换 scipy 积分器对照。
- **机制**：指到那一行。

### S3 LC 扫频（真实效应；与 X 正交）

- **问**：求三种调谐电容下谐振腔的谐振频率和有载 Q。
- **数据**：100 / 150 / 220 pF 各一份扫频。主谐振分别在 8.85 / 7.23 / 5.97 MHz（L = 3.23 µH）。
- **埋**：21.94 MHz 处有一个 5% 深的小谷，不随 C 移动。
- **好的检查**：
  - 它随不随 C 动；
  - 它是不是谐波（线性网络的 S21 不出谐波，比值 3.03 也不是整数）。
- **机制**：电感自谐振，分布电容约 16 pF。
- **S6 的例子**：据此估计寄生电容，说明 22 MHz 附近不能用。

### S4 棒的热导率（真实效应；X 有文献先验）

- **问**：真空中用加热功率 0.1–5 W 的稳态 ΔT 求 304 不锈钢样品的 κ（文献约 16 W/m/K）。
- **埋**：高功率处辐射损失让 ΔT(P) 向下弯。
- **朴素偏差**：目标 ≥ 10%。10-22 试算只有 4%（16.7）：要加大辐射面积，或降低导热截面。
- **好的检查**：残差的系统性弯曲、只用低功率点、和文献比。
- **机制**：辐射 ∝ εσA(T⁴ − T0⁴)。

### S5 半衰期（仪器伪影；X 有文献先验）

- **问**：从盖革计数求活化样品 ¹²⁸I 的半衰期（文献 24.99 min）。
- **埋**：死时间 100 µs，初始真实计数率 8000 cps。早期计数丢 44%。
- **朴素偏差**：拟合得 29.5 min，偏 +18%。
- **好的检查**：对数计数率早期弯曲、和文献比、只用后期数据。
- **机制**：死时间校正 m/(1 − mτ)。

### S6 摆的周期（真实效应；与 X 正交；先验：傅科）

- **问**：从视频追踪的二维摆锤位置求周期和阻尼。
- **数据**：1 小时；元数据写明实验室纬度 48.15°N。
- **埋**：摆动平面每小时转 11.2°。
- **防伪影的设计**：数据里放两个固定标记点。如果是相机转了，标记点也会转；埋点版里它们不动。
- **好的检查**：转动是否匀速、速率是否等于 15.04°/h · sinφ、标记点动没动。
- **机制**：地球自转。

## 6. 判分

- **S5，机械判分**：从 ANSWER 行读 X（2a/2b 从 results.json 读），和真值、朴素值比。
- **S1–S4、S6 和虚报，由评委判。**
  - 两位评委：deepseek-v4-pro 和 glm-5.3，都不是选手的厂商（CLAUDE.md 的规矩）。
  - 评委读报告和过程摘要（工具调用的命令和截断后的输出）。每个阶段答"是/否"，并给一句原文引用。
  - 引用由脚本逐字核对，对不上就记"否"。
  - 两位都说"是"才算"是"。分歧逐条列出，由我按引用裁决并记录。
- **判分器先验证，再开跑。**
  - 每个任务手写 4 份假报告：完整追到底、注意到但解释掉、没注意到、对照里虚报。
  - 评委必须全部判对，类比 simbench 的植入错误。

## 8. 判定线（开跑前写死）

每个臂 18 个埋点运行：

1. **臂 1 的 f ≥ 0.6**：在前沿模型上，"追意外"不是差异点。Luxas 的定位回到验证，不建意外机制。
2. **臂 1 的 n ≥ 0.5 而 f ≤ 0.35，且 2b 的 f 比臂 1 高 ≥ 0.25、2b 的虚报率不超过臂 1 + 0.15**：分离验证者是可测的优势。投"意外账本 + 强制处置"，下一步测"意外能不能改问题"。
3. **2a ≈ 2b，且两者都比臂 1 高 ≥ 0.25**：杠杆是执行端提示词，不是审稿人。
4. **各臂的注意率都 < 0.4**：杠杆在"先写预期"。跑 1b。
5. **其余情况**：不下建造结论，写明是哪种不确定。

n = 18 时功效很低：0.25 的差约等于 4–5 次运行。所以这些判定只决定方向（建不建），不当作可发表的效应量。要发表，第二批每臂扩到 6 次。

## 9. 效度威胁和对策

- **记忆**：数据新生成、参数随机，答案不在训练语料里。机制本身（死时间、傅科）是教科书知识，这正是要测的："先验来自 agent 自己的知识"。
- **题面泄露**：题面不出现提示词，各臂同一题面。2a 的方法论提示词是处理本身，不算泄露。
- **埋点太明显或太隐蔽**：用试点校准；只用试点调参，正式用新种子。
- **评委偏差**：非选手厂商、逐字引用、两位都同意才算，并且先用假报告验证。
- **带偏和探索混在一起**：S5 单独计。追了意外但 X 答错，记为"带偏"。
- **绕开埋点**（S2：agent 自己写积分器，没用给定的那个）：记为"X 对、没注意到"，单独报告这种运行有多少。
- **执行条件不一致**：执行都走订阅，缓存条件一致；模型和 effort 固定，开跑前打印出来。

## 构建记录（2026-10-22）

建在 `surprisebench/`：
- 生成器 `_lib/generate.py`；
- 每个变体一份 `RESEARCH.md` 和 `oracle.json`；
- 判分 `scripts/surprise_score.mts`；
- 验证用例 `_validation/cases.json`；
- gate `smoke_surprisebench`。

和上面设计不同的地方：
- **S3 的埋点改成夹具谐振**，不再是电感自谐振。
  - 并联谐振腔里，线圈的分布电容只是加到 C 上，不会单独出一个峰。照原设计生成的数据在物理上自相矛盾。
  - 谐振腔另加 4.7 pF 杂散电容：从 f0(C) 能拟合出来，这是 S6 的一个例子。
- **S4 的样品换成 2 级纯钛**，不再用 304 不锈钢。
  - 不锈钢的 κ 从 300 K 到 500 K 真实地升高约 15%，agent 可以正确地用 κ(T) 解释这个弯曲，而合成数据里并没有 κ(T)。钛的 κ 随温度略降，不能这样解释。
  - 参数：εA = 2.6e-5 m²。
  - 结果：朴素直线 +12%，只用低功率点 +6%，带 T⁴ 项的拟合 −0.6%，容差 4%。
  - 300 K 附近的辐射电导和导热一样是线性的，所以只用低功率点去不掉它。
- **S1 的参数**：第二个模式 Q = 30000、幅度 0.5。朴素单指数拟合全程 +42%，只拟合前 2 s 是 −40%，结果随拟合窗口剧烈变化。按原参数（Q2 < Q1）只偏 1%。
- **假报告**：24 份，不是 36 份。埋点任务每个 3 份（追到底、注意到但解释掉、没注意到），对照每个 2 份（干净、虚报）。共 99 个阶段判定。
- **判分器验证**：99 个判定全部和预期一致，验证花费合计 $0.78。为此修了三处：
  - **我写的判分器有 bug**：读报告时对 Markdown 也去掉 `%` 之后的内容，把"提高约 30%（从 0.054 到 0.070）"截成了半句，两位评委于是都判"没有预测"。现在只对 `.tex` 去注释，gate 里有对应的变异检查。
  - **S1 判据**："注意到"原来写成"认出这不是单模式"，把注意和解释混在一起。现在是"提到这个特征，不管归因于什么"。
  - **虚报判据**：原来要求"因此改了结果"，所以声称积分器有 bug、但数没变的报告漏判。现在是"把不存在的缺陷当成发现"本身就算。
- **评委设置**：GLM 5.3 必须设推理档位（它总在思考，不设就 400），用 low。DeepSeek 一次约 $0.002，GLM 约 $0.01–0.02。

**汇总：**
- 注意率 6/6，追到底率 6/6，S6（提出新问题）4/6。
- 对照 0/3 虚报。但 c5 没交付：它在干净数据上先得到 25.09 min，然后跑蒙特卡洛和 MCMC 去验证估计量，还考虑了 NaI 活化产生的 ²⁴Na 分量，40 分钟到了还在等后台任务。埋点版同一题 9 分钟。
- 几个追问的例子：
  - s1 提出把四象限光电二极管转 90° 来区分两个模式的形状；
  - s5 提出独立测量死时间；
  - s4 提出镀金或加辐射屏蔽，并预言 P/ΔT 会变成常数。

**按事先写的试点规则**（"埋点既不是 9/9 都被追到底，也不是 0/9 被注意到；不行就调强度"），这一版难度到顶了：臂 2 不可能超过 100%，照原样跑正式对比分不出臂。在这个设定下，判定线 1 的方向已经很清楚。这个设定是：短的单问题任务、一个埋点、干净的合成数据、xhigh effort。

**和外部证据的关系：** 外部测到的失败（AutoResearchEval：诊断出缺陷照样交付）发生在长程、多步、有交付压力的研究里，不是十分钟的单问题任务。所以试点说明的是"在受控的短任务里，前沿模型已经会追意外"，和定位笔记 §3 的结论一致。它没有回答长程研究里的情况。

**评分器：**
- 试点暴露了评分器的五处问题，修复在提交 `a32d288`：评委失败被当成"否"；LaTeX 的引用对不上；拼接的引用；JSON 里的反斜杠；（之前的）Markdown `%`。修完后在 24 份用例上重新验证，99/99。
- GLM 5.3 在真实大小的报告上不可靠：两次超长，单次最多 $0.48。正式跑之前要换第二评委，或者改成单评委加逐字引用。

**花费：**
- API $3.44：评委验证 $1.22，试点评判 $2.15，调试 $0.07。
- 执行走订阅，按标价折算 $22，不计费。
